# news/ — RuTerm release notes

Plain Markdown files. One `.md` per release/entry. The app loads these automatically:
what you see in the **What's New** tab is the same content that lives here.

## Writing an entry

1. Create `news/YYYY-MM-DD-short-slug.md` (date prefix is how the app orders entries).
2. Start the file with `# Your title` — the first heading becomes the entry title.
3. Keep it short and human: what changed, why you should care.

That's it — `npm run dev` / `npm run build` regenerates the bundle automatically
(the `predev`/`prebuild` hook runs `news/build-index.mjs`).

## How it reaches the app

- **Bundled**: `desktop/static/news/` is generated from this folder at dev/build time —
  the app works offline with the last bundled state.
- **From GitHub** (once the repo is public at `github.com/dnysaz/ruterm-app`):
  the app fetches `news/index.json` + the `.md` files from
  `raw.githubusercontent.com/dnysaz/ruterm-app/<pinned-commit>/news/` on every
  launch. The commit is pinned in `desktop/src/lib/news.svelte.ts`
  (`NEWS_COMMIT`); update it when publishing a release. Push a new entry → it
  shows up with a +1 badge on the What's New button, no app rebuild needed.
- `news/index.json` is generated by the same script and **committed** — the app
  reads it remotely, so keep it in sync (`node news/build-index.mjs`, runs
  automatically via npm hooks). Every entry carries a `sha256` digest; the app
  verifies each body against it before rendering or caching, so a tampered
  feed is discarded rather than shown.

## Format cheat sheet

- Headings: `#` title, `##` sections inside the entry.
- Code: fenced blocks with triple backticks.
- Lists, bold, inline code, links. Raw HTML is sanitized out.
